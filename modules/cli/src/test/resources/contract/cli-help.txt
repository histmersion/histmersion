Histmersion — CLI over the Histmersion server (MCP twin)

Options and flags:
    --help
        Display this help text.
    --server <string>
        Histmersion server URL (default: config cli.serverUrl / $HISTMERSION_SERVER_URL)
    --by-plugin <string>
        An automated caller: the plugin it runs in, named on what it creates (else $HISTMERSION_AGENT_PLUGIN)
    --by-workflow <string>
        An automated caller: its workflow (else $HISTMERSION_AGENT_WORKFLOW)
    --by-agent <string>
        The agent's definition, with --by-provider and --by-model (else $HISTMERSION_AGENT_DEFINITION)
    --by-provider <string>
        The agent's AI provider (else $HISTMERSION_AGENT_PROVIDER)
    --by-model <string>
        The agent's model (else $HISTMERSION_AGENT_MODEL)

Subcommands:
    version
        Print the CLI and server versions
    health
        Server health (db, schema version)
    about
        Server build (version, commit), health, job queue, last backup, store counts and storage on disk
    seed
        Import a wiki/ or wiki/sources directory (articles beside it come too) — read on the HOST when that path exists here, otherwise asked of the SERVER (empty = configured corpus dir)
    reindex
        Rebuild the full-text chunk index for every source
    search
        Search the corpus (websearch syntax: "phrase", -not, or): sources with the findings that matched
    facets
        Vocabulary of a dimension (tags|authors|places|topics|status|provenance) with distinct-source counts
    get
        Show one source as Markdown (section: summary|findings|notes|toc|body|all)
    passages
        Find a word, phrase or regex inside one source's full text: the passages around each match, with offsets for get --offset
    geo-when
        Findings (the map feed) by place, deep time, bbox — the same filters as `search`
    histogram
        When is the evidence? Sources per adaptive time bucket (Markdown table + bar chart), for the same filters as search
    neighbors
        Typed references to/from a source (references, challenges, refutes, updates, superseded_by)
    graph
        Source dependency graph: BFS traversal returning D3-ready nodes + links
    contradictions
        Disagreement edges (challenges, refutes, updates, superseded_by) and contested/superseded/debunked/retracted statuses
    put
        Send ONE note file (frontmatter + body) as a full create/replace
    patch
        Selectively enrich one source — only the parts you pass are changed
    rename
        Give a source a new citekey — findings, links in articles/notes and every table follow. The old citekey stays an alias: every read and every write that names it (put, patch, delete, rename, a reference) goes to the record under its new citekey, and the answer names the new citekey.
    delete
        Delete a source with its findings, edges, figures and stored original — a dry run unless --apply; refused while an article cites it; Calibre is never touched
    export
        Write sources to <dir>/sources/, articles to <dir>/<kind>/, bookkeeping to <dir>/meta/ — the seed layout
    backup
        Take a pg_dump backup of the server's database (optionally copy it here)
    backups
        List the backups on the server, newest first
    restore
        Restore a server-side backup (pg_restore --clean); refuses a non-empty database without --force
    maintenance
        Database upkeep on the server: vacuum
    bundle
        Portable .hmx bundles: export, verify and import a whole collection, carrying its identities
    merge
        Merge another collection's bundle into this one: plan it (every issue in one run), apply it; list, show and trace past merges
    article
        The compiled wiki: list/get/put/patch/lint/check/coverage/review/rename/export/import/versions articles
    places
        The gazetteer: search, show, rename, name, set, merge, rm, add, import, load external sources and materialise places
    periods
        Named periods (the timeline presets): search, show, seed and fetch from PeriodO
    init
        Import the bundled gazetteer and period presets (a server job); --fetch adds the network sources
    events
        Historical events: search, show, patch, rename; import and re-derive catalogues, corrections, links to sources, leads
    attestations
        Granular source references: search, show, add, rm
    candidates
        New sources found for the research goals without a model: list, sweep, mark
    goals
        Research goals: list, get, update, plan, link, unlink, schedule, schedules, rename
    agent-state
        Agent state key-value store: list, get, set
    agent
        Embedded research agents: models, allowance, quota, generate, doctor, probe, run, runs, show, compare, pause, resume, cancel, approvals, approve, reject, digest, decide-all, managers, manager, enqueue, autopilot, scheduler, stalls
    media
        Pictures: import from providers, covers and illustrations of sources, list, show, fill-licences; a figure's detail, patch
    asset-links
        Semantic links between assets and entities: search, add, rm
    lint
        Health-check the corpus (34 rules: dangling-edges, unresolved-short-citekeys, no-findings, no-period, no-regions, empty-summary, unassessed-status, duplicate-doi, duplicate-sha256, orphan-sources, stale-chunks, undated-findings, unlocated-findings, legacy-figure-links, dangling-article-links, non-canonical-tag, missing-year, year-citekey-mismatch, author-pipe, article-filler, article-uncited-paragraph, article-thin-summary, article-critique-pairing, superseded-without-edge, article-markdown, note-markdown, finding-geocode, finding-unplaced, place-kind, place-grid-point, place-imported-point-area, finding-placeholder, media-licence, event-correction-conflict)
    queue
        Bookkeeping queues: acquire / tasks / log — show, add, done, edit, rm, export (with the goals as GOALS.md), import; acquire recheck: the legal re-check of the acquisition list (more than one item, or --all for every item past the caps, as a server job it follows)
    query
        Run ONE read-only SQL statement (a write is refused by Postgres itself)
    schema
        List the tables and columns `query` can read (from information_schema)
    discover
        Find literature upstream (OpenAlex / Crossref / Wikipedia)
    refs
        The reference list a paper deposited, resolved against the corpus
    assess
        Retraction / correction / impact verdict for a paper (retracted|corrected|current|low-impact)
    followups
        Papers citing this one, with intents and a proposed edge kind (confirms|challenges|refutes|supersedes|cites)
    ingest
        Bring a paper in: a local PDF/EPUB (uploaded and OCR'd, keeping its figures) or an identifier (metadata → legal OA PDF → the same OCR job → reference edges → assessment)
    archive
        Internet Archive: search, inspect and import public texts
    calibre
        The local Calibre library: search, import, link, push, update, set, audit, sync, gaps
    reocr
        Convert a source's stored original again (e.g. under the slow, accurate OCR path)
    assets
        The figures stored with a source, and the URLs they are served at
    jobs
        Recent background jobs (OCR, imports, agent runs, …), filtered on the server, or one job by id; `jobs pause|resume|cancel <id>` controls one
    activity
        What the agents, the server and you did, one list, newest first: agent runs, background jobs, worklog lines and your decisions, each with what it touched
    log
        What happened, step by step: answered requests, provider calls, problems and database writes, each with the trace that links one request's or job's steps
    state
        The research state: what waits for you (decisions, acquisitions, tasks, paused runs) and what the agents will handle
    bookmarks
        Your bookmarks: list, add, rm
    notes
        Your notes: list, show, add, edit, rm
    config
        The settings file: where it is, its settings (get, set, unset — the file is changed in place, comments and all), reloading and restarting the server
    basemap
        The web UI's local base map (street maps and terrain): status, styles, fetch, rm
    plugin
        Plugins of the Histmersion installed on THIS machine: add, rm, list, status, rebuild, rollback (refused when the CLI points at another machine); new, repo and api-jar for writing one

==== histmersion search
Usage: histmersion search [--group <string>] [--depth <integer>] [--as-of <integer>] [--samples <integer>] [--unit <string>] [--brief] [--tag <string>]... [--author <string>]... [--place <string>]... [--topic <string>]... [--status <string>]... [--year-from <integer>] [--year-to <integer>] [--from <integer>] [--to <integer>] [--bbox <string>] [--sort <string>] [--limit <integer>] [--offset <integer>] [--title <string>] [--goal <string>] [--json] [<query>]

Search the corpus (websearch syntax: "phrase", -not, or): sources with the findings that matched

Options and flags:
    --help
        Display this help text.
    --group <string>
        Group the results into a tree instead of listing them: time | region | time,region | region,time
    --depth <integer>
        Levels of nesting for --group (1-3)
    --as-of <integer>
        Signed year the gazetteer hierarchy is read at for --group region (default: the middle of the window)
    --samples <integer>
        Sample sources listed under each leaf of the tree (0-5)
    --unit <string>
        What --group counts: sources (default) | findings
    --brief
        Compact listing: citekey, title, year, status, period, one why-line
    --tag <string>
        ALL required — every tag must be present on the source or one of its findings (repeatable)
    --author <string>
        ANY matches — a case-insensitive substring of an author's name (repeatable)
    --place <string>
        ANY matches — a place id from `places` matches by geometry and hierarchy, a name matches text (repeatable)
    --topic <string>
        ALL required — every topic must be present on the source (repeatable)
    --status <string>
        ANY matches — foundational|current|contested|superseded|debunked|retracted|unassessed (repeatable)
    --year-from <integer>
        Earliest publication year (inclusive)
    --year-to <integer>
        Latest publication year (inclusive)
    --from <integer>
        Deep-time start, a signed year (BCE negative: 1200 BCE is -1200)
    --to <integer>
        Deep-time end, a signed year (BCE negative)
    --bbox <string>
        minLon,minLat,maxLon,maxLat (minLon > maxLon crosses the antimeridian)
    --sort <string>
        Ordering: relevance|cited|period|year|oldest|title
    --limit <integer>
        Results per page (default: the configured page size, at most 500)
    --offset <integer>
        Skip this many results — the next page's offset is in the list's footer (`next: offset=N`)
    --title <string>
        Case-insensitive substring of the listed item's title
    --goal <string>
        Only the sources a research goal links (its slug)
    --json
        Print the raw JSON response instead of Markdown

        Subscription pools (Claude plan, ChatGPT plan): each window's use, its floor, reset and reading age; the hold switch; metered allowances

        Write the per-runtime agent definitions (Claude Code plugins, Codex home, opencode config) from the server's bundled agents and skills — on the SERVER's disk
    doctor
        Check every provider without spending anything: keys, the free model listing, prices, the claude CLI and its login
    probe
        One live model call with one read-only tool (get_source) and a typed answer, checked against the record
    run
        Start a pipeline on a target (enrich-source <source>, review-article <article>, plan-goal <goal>, compile-article <article>, currency-check <goal>, acquisition-sweep <goal>, infer-filter <article>, hint-effect <manager>, propose-articles <goal>)

        Agent runs, newest first, filtered on the server

        One run: its steps — tokens (with the first call's input and the turns), cost — and warnings (and --messages: the trace)
    compare
        Runs of one pipeline on one target side by side: per step the model (configured → reported), tokens, the first call's input and the turns, cost or plan pool, time and attempts; then the outputs (enrich-source: findings, quote check, places, periods, summary and notes, the claims only one run made; review-article: verdicts, findings per reviewer and kind, the major findings runs share)
    pause
        Pause a run before its next step
    resume
        Resume a paused run (finished steps are replayed, not re-run)
    cancel
        Cancel a run
    approvals
        Changes runs proposed for a person to decide (statuses, disagreement edges, goal plans, articles to publish, …), filtered on the server; the open ones by default
    approve
        Approve proposed changes (one or more ids): a source change is applied through the ordinary patch; a plan or an article lets its waiting run go on and apply it
    reject
        Reject proposed changes (one or more ids; they stay on record)
    digest
        Everything waiting for a person in one view: the open approvals by kind (how many, the oldest, who decides them now, the subjects with the most, the ids) and the manager items held for a person; once a day it is also written to the worklog (agents.autopilot.digest-hour)
    decide-all
        Approve or reject every OPEN approval that matches at once — of a kind, about a subject, or the ids given (they narrow together; one is needed), the oldest first, each through the same decision a single one takes
    managers
        The process managers: each one's state, items, runs in flight, status line and last event
    manager
        One process manager: new, or <id> status|items|events|pause|resume|stop|hint|enqueue|hold|release|skip|reopen|priority|cron|config
    enqueue
        Hand a target to its manager, as the page buttons do: review|extend <article>, enrich <citekey|article|goal> (the unenriched sources it cites or links), seed <goal> (propose its next articles); a missing manager is created paused
    autopilot
        The autopilot: status (default) — per research goal its stage, managers, sources, articles, open approvals, last activity and pace, and the watchers' ingest backlog; on — every goal gets an active seeding manager and watcher and moves from planned to reviewed by itself (within every cap, budget and plan floor); off — the seeding managers and watchers it runs are paused; repair-acquire [--dry-run] — move the acquisition items a watcher's sweep created for legal open-access works into the watchers' ingest backlog (a person's items are never touched); focus [list|pin <goal>|unpin <goal>|priority <goal> <n>|max <n|default>] — at most max-active-goals goals are active for model work (finish-first: articles to review, then to compile, then enough sources; depth-first within a tree; a person's pins and priority; then the oldest), the others' model-using items wait; ingestion is not capped; drain — nothing new starts while the runs in flight finish (the status says DRAINED once none is queued or running: safe to stop the server for a deploy); undrain — lift it (turning it on lifts it too); mode <working|finish|pause> — the two switches as the web UI's one choice: working, finish current work then pause (on and draining), pause now (off)
    scheduler
        The central scheduler that admits the managers' work across every job type: status (default) — the strategy, the runs at once and plan pools, the job types' shares, what the last pass started and the queue with why each item waits; queue — only the waiting items, in the order they would start; why <item> — one item (its id, or the target of an open item): waiting behind what, running, waiting for a person, held, settled; strategy <type-balanced|goal-first|default> — switch it live (default: back to agents.scheduler.strategy)
    stalls
        The unfinished research goals with no progress in N days (default agents.autopilot.stall-days), each with the one reason it stands still — draining, waiting for a person, held, paused, a budget, quota, the scheduler's queue, a block, a failed item, no candidates, idle — and the command that unblocks it

==== histmersion basemap fetch

        Print the job id and return instead of following it

==== histmersion plugin
Usage:
    histmersion plugin add
    histmersion plugin rm
    histmersion plugin list
    histmersion plugin status
    histmersion plugin rebuild
    histmersion plugin rollback
    histmersion plugin new
    histmersion plugin repo
    histmersion plugin api-jar

Plugins of the Histmersion installed on THIS machine: add, rm, list, status, rebuild, rollback (refused when the CLI points at another machine); new, repo and api-jar for writing one

Options and flags:
    --help
        Display this help text.

Subcommands:
    add
        Install a plugin on this machine: a local path (copied, with the .pom beside it), an https URL (downloaded, SHA-256 shown) or group:artifact:version from Maven (group::artifact:version = a Scala 3 artifact); the dependencies its POM lists are installed with it, except what Histmersion ships; shows its id, version, SPI, access and dependencies first
    rm
        Remove an installed plugin (by id or jar file name) from this machine's plugins directory
    list
        The plugin jars in this machine's plugins directory, and whether the installed binary was linked with each
    status
        Compare the plugins directory's digest with the installed binary's and the running server's: is a rebuild (relink) or restart needed? Also the kit and signing
    rebuild
        Relink the server with the plugins directory (bin/histmersion-relink: pre-flight, native-image, self-check, swap, restart, health; the previous binary comes back on failure)
    rollback
        Put the previous server binary back (the one before the last relink) and restart
    new
        Write a new plugin project for scala-cli: project.scala (the build), <Name>.scala (the plugin), <Name>.test.scala (its tests) and resources/ (its services file, defaults, native-image metadata)
    repo
        The Maven repository of this machine's install that a plugin compiles against: the plugin API, histmersion-plugin-platform (the libraries Histmersion provides, at the versions it ships) and the plugin testkit; --url: as a file: URL; --m2: copy it into the local Maven repository (~/.m2/repository), which a build names as m2Local (scala-cli) or Resolver.mavenLocal (sbt)
    api-jar
        The path of the plugin API jar in this machine's install's Maven repository; --sources: of its sources jar, with the Scaladoc
