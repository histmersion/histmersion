# MCP tools

The MCP endpoint is `<public-url>/mcp` (by default `http://localhost:8000/mcp`). How to connect an
assistant: [Using your AI assistant](../ai-assistant.md). Every tool runs the same handler as the
matching REST endpoint and CLI command, and returns Markdown.

**80 tools**, wired for Claude Code through `.mcp.json` (`type: http`, `<public-url>/mcp`, written
by `just mcp-json`, which `just install` runs). Every tool returns Markdown. The table below is refreshed from the server's own
`tools/list` — that endpoint, not this file, is the authority on what exists.

Deep time everywhere is a **signed integer year**: 1200 BCE → `-1200`.

## Read

| tool | when to use it |
|---|---|
| `ping` | liveness + schema version. First call when anything looks wrong. |
| `search` | **the entry point for any topic question.** Free text (websearch syntax: `"phrase"`, `-not`, `or`) plus every filter: `tags`/`authors`/`places`/`topics`/`status`, `yearFrom`/`yearTo`, a deep-time window (`from`/`to`), a bbox, `sort`. The SOURCE is the unit of each hit, which lists the findings that matched and why. `groupBy` = `time\|region\|time,region\|region,time` returns a nested tree of counts instead of a list (`depth` 1–3, `asOf` picks the year the hierarchy is read at). Counts are **non-additive** — a source lands in every bucket it overlaps. |
| `facets` | the vocabulary of one dimension (`tags`, `authors`, `places`, `topics`, `status`) **inside the current filter**, with distinct-source counts. Call it before guessing a tag: an unknown tag returns nothing. |
| `get_source` | after `search`: metadata, summary, notes and findings for one citekey. `fullText: true` pulls the whole OCR'd body — mean 450 KB, **max 5.7 MB** — so use it sparingly; a `search` snippet is usually the sentence you wanted. |
| `passages` | **to find what one source says about a term** — `grep` over one body: the passages around each literal match (case- and accent-insensitive; `regex: true` for a Java regex), each with the heading it sits under and the body `offset` that `get_source` reads on from, then how many more there are. |
| `geo_when` | "what happened *here*, *then*" — individual findings by `region` name, bbox (antimeridian-safe) and `periodStart`/`periodEnd`. |
| `histogram` | "when is the evidence" — sources or findings per adaptive time bucket, the same aggregation the web UI timeline draws. |
| `neighbors` | **before relying on a claim.** The typed edges to and from a source, plus the articles that cite it. Stored kinds are `references`, `challenges`, `refutes`, `updates`, `superseded_by`; only the last four are disagreement. Edges join stored sources; one pointing at a work not in the corpus yet is listed as unresolved. |
| `graph` | the citation network around a source, breadth-first to `depth`: nodes (citekey, title, year, status) and typed links — what the web UI's graph window draws. |
| `contradictions` | disagreement edges and contested statuses: for one `citekey`, both directions with the other side's year and status; without one, corpus-wide. An empty answer is not evidence of agreement. |
| `periods` | **named periods** (PeriodO definitions: Bronze Age, Late Minoan IB, Old Babylonian, Yamnaya…). Without `id`: search by label, `region` or overlap with `from`..`to`; with `id`: span, region, the authority that states the range, what it is part of and how it is divided. Turns a period name into the years to pass to `search`/`geo_when` — cite the authority, since authorities date the same name differently. |
| `places` | **the gazetteer.** Without `id`: a name a human wrote ("Anatolia", "Ugarit") → a place **id**; pass that as `places` to `search` and it matches everything inside the shape *and* below it in the hierarchy, which a bare name never does. With `id`: geometry, validity, parents and subtree. `asOf` reads the hierarchy as it stood in a given year. |
| `list_articles` | the **compiled wiki** — list/search articles by `kind`, full-text `query` (the article's own title/summary/body), `title` (substring), `tag` (articles citing a source with that tag). Call it before compiling anything; the topic may already have an article to extend. |
| `get_article` | one article by slug: body, the **generated coverage sections** (Not used + Method, when it records a filter), **backlinks**, and the **sources cited** with title · year · status — and a **Formatting** section listing what in the Markdown will not display as written (line, column, excerpt). |
| `article_coverage` | **an article's filter against the live corpus** (#958): how many sources the filter it records returns, which the body cites, every other one with its stored reason (or "not yet assessed"), the status breakdown, the disagreement edges touching the cited sources, the further searches, the **drift** — sources neither cited nor given a reason, stale reasons — and the **critique checklist** (*Disagreements checked*: each challenges/refutes/updates/superseded_by edge touching a cited source, *addressed* when both sources are cited in one paragraph, *reasoned* when a critique reason is stored, else *open*), then the Not used list and `_Method_` note exactly as the page generates them. CLI: `histmersion article coverage`. |
| `article_review` | **where an article stands with the review panel**: its state (*unreviewed*, *queued*, *in-review* with the round, *passed*, *majors-open*, *stopped*) and what it means, the review manager's last outcome, the research goals that link the article with their stage, the approvals about it waiting for a person, and its **review history** from the review ledger — every finding by run and round with reviewer, kind, place, problem and what became of it (fixed, rejected with the record's sentence, won't fix, still open). CLI: `histmersion article review`. |
| `article_versions` / `article_version` | an article's edit history (newest first), and the full body of one past version — to see what a rewrite changed or recover text a bad patch overwrote. |
| `check_edits` | **dry-run a change to an article, writing nothing**: `edits` (`{op: replace\|insertAfter\|insertBefore\|delete, anchor, text}`, applied in order to the stored body, each anchor found exactly once) or a whole draft `body`, checked exactly as `review-article` checks its fixer's answer — each edit's fate, then the result's links to nothing, uncited paragraphs, Sources cited heading, filler and new formatting errors, and whether one is fatal. CLI: `histmersion article check`. |
| `schema` | the tables, columns and types `query` can read, from the live `information_schema` — check names before writing SQL. |
| `query` | one **read-only** SQL statement for what the other tools cannot express. Runs in a `READ ONLY` transaction with a statement timeout and row cap; the description lists the live tables from `information_schema`. |
| `lint` | **after a batch of ingestion.** 25 corpus-integrity rules (dangling edge targets, unresolved short citekeys, sources with no findings/period/regions/summary, `unassessed` status, duplicate DOI/sha256, orphans, stale chunks, undated/unlocated findings, the wave-3 tag/year/author/article checks, `legacy-figure-links` — bodies whose figures still point at a `figures/…` path — `dangling-article-links` — `[[wikilinks]]` that resolve to no source and no article — and the formatting rules `article-markdown` / `note-markdown`, see [Formatting lint](formatting-lint.md)). `fix: true` applies the two safe repairs. With `article` (a slug), `source` (a citekey) or `text` (Markdown not stored yet) it checks just that one for formatting problems, and `fix: true` applies the wording-safe repairs to it. |

## Write

| tool | when to use it |
|---|---|
| `put_source` | create or **replace** a whole source. Destructive — creation and deliberate re-import only. |
| `patch_source` | **the enrichment tool.** Send only what changes: `metadata`, `summary`, `body`, `notes`, `topics`, `regions`, `period`, `tags{add,remove,replace}`, `findings{add,remove,replace}`, `edges{add,remove}`. `ifUpdatedAt` returns 412 instead of clobbering. The answer lists formatting problems in the summary and notes; `strict: true` refuses a patch whose summary/notes have a formatting error. |
| `rename_label` | give an article a new slug, an event a new id, a goal a new slug or a place a new gazetteer id (`kind`: article · event · goal · place): what points at it follows (an article's `[[old]]` links in other articles, each a recorded version; an event's attestations and asset links; a goal's sub-goals, links and schedules; a place's names, parents, footprints, events, attestations and finding assignments) and the old label stays an alias: every read and every write that names it (put, patch, delete, rename, a reference) goes to the record under its new one, and the answer names the new one — for a place, a `place=<old id>` filter too. |
| `place_names` | names **added by hand** to gazetteer places — the ones every re-seed keeps. Without `name`: lists them (of `placeId`, or all); with `placeId` + `name` (+ `lang`): adds one ("Lake Kinneret" for the Sea of Galilee) so the geocoder and `places=` filters know it; `remove: true` drops one added by hand (a seed name cannot be removed). |
| `place_override` | **curate a gazetteer place by hand**, over what its source says, kept by every re-seed and re-import: `placeId` + `kind` and/or `periodStart`/`periodEnd` sets what it IS (a Pleiades "urban" site that is one of Rome's 14 regiones → `region`), and its findings are matched again at once; `pointLat`/`pointLon` (with a `reason` naming the gazetteer value) moves a place known by a point whose stored point is wrong (a shape is never replaced; `lint --rule place-grid-point` then leaves it alone); `reset: true` restores the source's kind, period and point; `mergeInto` merges a duplicate into the place it is (findings, links and references move, its id resolves there); `remove: true` deletes a place nothing refers to. `reason` records the evidence. Without a change: lists the overrides with what each source says. |
| `add_place` | a **point place** the gazetteer lacks, after `places` found it under no name: `label`, `kind`, `lon`/`lat`, and a required `source` for the point (never an estimate). It is this collection's own (`local_<label>`), carried in a bundle and untouched by a re-seed. |
| `rename_source` | give a source a **new citekey** (e.g. the year in it is not the publication year). One transaction: findings renumbered, every table and every `[[old]]` link in articles (each rewrite a recorded version) and source notes follow. The old citekey stays an **alias** — reads, writes (`put_source`, `patch_source`, delete, rename), `/source/<old>` and `[[old]]` go to the source under its new citekey, and the answer names it. |
| `put_article` | create or **replace** a whole article. Cite sources as `[[citekey]]`; write it by [`docs/writing-guide.md`](https://github.com/histmersion/histmersion/blob/master/docs/writing-guide.md). The answer lists its formatting problems; `strict: true` refuses one with an error. |
| `patch_article` | **the way to extend an article**: `append` adds Markdown at the end of the body; or send `body`/`title`/`summary`/`kind`/`regions`/`period`/`tags{…}`. `filter` records the filter the article is compiled from (`{}` clears it) and `reasons` `[{citekey, reason}]` why each of its sources the body does not cite is left out (an empty reason removes one): the page then **generates** the Not used list, its counts and the `_Method_` note — nobody writes them. `critiqueReasons` `[{src, dst, reason}]` sets why one pair of the critique checklist does not bear on the article (an empty reason removes it; refused without a disagreement edge between the two; stored beside the article, so it leaves `updatedAt` as it is; CLI `--critique-reason <src>><dst>=<why>`). `ifUpdatedAt` guards. The answer lists the formatting problems of the article as patched; `strict: true` refuses the patch when the result has an error. |
| `queue` | the project's bookkeeping in one tool: `action` = `list`\|`add`\|`done`\|`recheck` over `acquire` (what the USER must obtain), `tasks` (the agent's backlog), `log` (the dated worklog). Use it instead of writing a tracker file. `list` on `acquire` shows under each item its last legal re-check; `recheck` runs that re-check now (closes the items the corpus holds, tries a few due ones through the legal chain only; `id` = one item, `limit`, `dryRun`; `all: true` = every open item with a DOI, due or not, past the daily caps). A pass of more than one item runs as a server job — the answer names it; follow it with `job_status`. |

## Acquisition

| tool | when to use it |
|---|---|
| `discover` | **literature we do NOT have yet.** `query` searches OpenAlex, `doi` fetches one paper's metadata, `wikipediaUrl` harvests every DOI a Wikipedia article cites (supplementary, after the database searches and the citation graph). Each hit carries the citekey it would get; `notInDb: true` gives the delta. |
| `ingest_doi` | bring a paper in by DOI or `arxiv:<id>`: metadata → legal OA PDF (Unpaywall → CORE → OpenAlex OA → Europe PMC/PMC → arXiv → repository landing pages resolved one step: Zenodo, an institutional repository's `citation_pdf_url`; else PMC's JATS full text, rendered without OCR — the acquisition chain, `acquire.chain`, each step a built-in plugin that can be switched off) → OCR job → reference edges → assessment. Idempotent; never wipes enrichment. A metadata-only source is fetched and converted; one with its original keeps it unless `refetch`. An agent's ingest asks the legal chain alone (`legalOnly`, on by default), never a fetcher the config marks unauthorised; `legalOnly: false` is refused unless a person switched `acquire.agents-may-use-unauthorised` on. |
| `ingest` | OCR a PDF/EPUB into a source **keeping its figures**. Takes a `path` the SERVER can see or a `base64` payload (≤ `limits.inline-bytes`); returns a **job id**, because a long scan takes minutes. `acquireItem` names the acquisition item the document fulfils: the job ticks it off when it succeeds. Without it, the job ticks off every open acquisition item that names the source's DOI and lists the items with a similar title as possible matches, never closing those. |
| `job_status` | where an OCR job got to — `queued\|running\|done\|failed`, its progress line or the reason it failed. No `id` lists recent jobs, filtered on the server by `status`, `kind` (`ingest`, `reocr`, `agent`, `media-import`, …), `since` / `until` (`2026-10-01`, an ISO instant, or `7d` / `12h` ago) and `subject` (text in what a job is about), headed `Latest N of M` when there are more and with a `By kind:` line of counts; `before: <id of the last job shown>` lists the next older page (with the same filters). |
| `job_control` | pause, resume or cancel a job by `id` (`action`: `pause` \| `resume` \| `cancel`). A long background job — a picture or event import, a base-map download, an acquisition re-check, the init job's gazetteer loads — stops after the part it is on: paused it keeps what it did and, resumed, goes on with the parts it had not done; cancelled it is recorded as `cancelled`. An agent run takes its own pause, resume and cancel; a job that runs as one piece (an OCR, a vacuum) is refused. |
| `activity` | Research › Activity: agent runs, background jobs, worklog lines and the person's own decisions in one list, newest first, each naming what it touched (goal, run or job, source, article, list item, approval). `show` = `all` (default) \| `running` \| `agents` \| `jobs` \| `yours` \| `problems`; `since` (`2026-10-01`, an ISO instant, or `7d` / `12h` ago); `goal` = one goal's history; `limit` (30, at most 200); `before` = the cursor the last page gave. |
| `bookmarks` | **Read only.** The person's own bookmarks, newest first: sources, articles, events, places, pictures and goals they marked, places on the map, saved views of Explore and periods. `kind` narrows to one; `query` = words the bookmark's name or the item's title holds; `limit` (200). No tool adds, changes or removes a bookmark — only the person, in the web UI or with `histmersion bookmarks`. |
| `notes` | **Read only.** The person's own notes (Markdown), last changed first, each with what it was left on (an item, or a place on the map). `id` = one note in full; `kind` + `item` = the notes on one item; `query` = words in the note or the item's title; `limit` (200). The person's thoughts, never evidence to cite. No tool writes a note — only the person, in the web UI or with `histmersion notes`. |
| `assets` | the figures stored with a source: name, mime, pixel size, and the URL each is served at. |
| `archive` | Internet Archive for out-of-print books: search, inspect, import. **Public items only** — a lending-only scan is refused. |
| `collection` | the library's source collections — the user's Calibre library (and archive.org): `list`, `search` (`unlinked`), `import`, `link`, `push` (`replace`), `update` (one, or every linked entry with `apply`), `set`, `audit`, `gaps`, `sync` (`apply`). Writes need the Calibre GUI closed and `plugins.calibre.write-back` on. |
| `candidates` | **new sources found for the research goals without a model** (#3761): each goal's saved queries on OpenAlex, Crossref, Europe PMC, arXiv (CORE with a key), the works citing its sources and its sources' authors' newer works, read from each watch's watermark and deduplicated by DOI against the corpus and the acquisition list. Lists the `new` candidates (of `goal`, or every goal; `state` for the others); `mark` + `as` records a decision (seen, queued, dismissed); `sweep: true` reads a goal's watches now (`dryRun`). |
| `refs` | the reference list a paper deposited with Crossref, resolved against the corpus; `apply: true` writes them as `references` edges. |
| `assess` | **before citing anything unchecked.** Retraction Watch + Crossref amendment notices + citation metrics → `retracted\|corrected\|current\|low-impact\|unassessed`; `apply: true` writes the verdict into `status`. `updateRetractions: true` refreshes the local mirror — **do that first, the mirror starts empty**. |
| `followups` | what came AFTER a paper: citing works with Semantic Scholar intents, influence flags and citation contexts, each with a proposed edge kind. A live network call — seconds per source. |

## Export and operations

| tool | when to use it |
|---|---|
| `export_source` | the source as the Markdown note it would be on disk (frontmatter + notes body) — the git-friendly mirror. |
| `export_article` | the article as the Markdown note it would be at `wiki/<kind>/<slug>.md`. |
| `backup` | a server-side `pg_dump`, returning the file name, size and SHA-256. |
| `config` | the server's settings, kept in its settings file (never the database). `get` (`key`, or `prefix` such as `acquire`): what the file says, what applies and from where, the default and what the setting does — a credential only as set or not and how it is referred to. `set` (`key`, `value` as a person types it) and `unset` (`key`): the file changed in place (comments, order, includes, anything written by hand kept; the old file kept as `.bak`), checked first — a refused change says why — then reloaded; a credential is written as a reference (`env:NAME`, `<vault>:<entry>`), `value:` only with `literalConsent`. `reload`: the server reads its config file again and applies it in place (no restart; the database too): what was applied, what needs a restart, what was rebuilt, any error — a broken config changes nothing. `restart`: a server running under its LaunchAgent or systemd unit restarts, for the settings only a restart applies. |
| `vacuum` | `VACUUM` (with `analyze: true`, `VACUUM (ANALYZE)`) of the named `tables`, or of `maintenance.vacuum-tables` (the gazetteer and finding tables a re-seed rewrites), as a server job, one table at a time outside any transaction; answers with the job (follow it with `job_status`). Use it after `places seed`, a gazetteer load or a place clean-up. |
| `backups` | the archives on the server, newest first — check one exists before a bulk operation. Restoring is `histmersion restore` (a human's call). |
| `merge_plan` | **read-only** plan of importing another collection's bundle (uploaded by `histmersion merge plan <file>`, named by its sha256): every source matched (by uid, ledger, DOI/file/ISBN or score), and EVERY issue in one run — two citekeys for one work, one citekey for two works, differing DOIs/years/statuses, rows changed on both sides, diverged articles — each with a stable id, the evidence and the allowed decisions (left = here, right = the bundle). `resolve` shows what would remain. Present the plan; scholarly decisions are the user's. |
| `merges` | **read-only**: the merges this collection took in (`action: list`), one merge's report, resolutions and remembered decisions (`show`, `id`), or the merge ledger of a record (`ledger`, `uid`: a uid or a citekey) — where a record came from and which merged-away uids redirect to it. Applying a merge is the user's (`histmersion merge apply`, or the `/merge` screen). |

## Events, evidence, assets and research memory

| tool | when to use it |
|---|---|
| `events` | the events database: CIDOC-CRM-style events with four-point time-spans, a part-of hierarchy, temporal/causal edges and participant roles. Lists (by `query` over label/description, `title` over the label, `kind`, `historicity`, `placeId`, `from`/`to` overlapping the event's own span), or shows one by `id` — each with its **scale** (`local` · `regional`, stated or derived). |
| `patch_event` | change fields of one event without replacing it: label, kind, historicity, description, citekey, parentId, `placeId` (where it happened), its own geometry (GeoJSON, or `lat`/`lon`), and `scale` — `local` (one place: a battle, a siege, a destruction) · `regional` (across a region: a migration, an era, a war) · `auto` (forget the stated one; derived from the kind, then its own geometry, then the place's kind: a site local, a region/polity/people regional; a sub-event with none of these is local). The map's playback draws a local event as a dot and label at its site that fade after it ends, a regional one as a label at the region's centre with the region's outline for its span. `wikidata` (`Q…`, `""` clears) is the item `histmersion media import` reads the event's picture from. On an event a CATALOGUE import created, every changed field is kept as a correction across re-imports (see `event_corrections`). |
| `event_corrections` | the fields of catalogue events (GVP, NOAA, Wikidata) a person corrected by hand — each kept over the catalogue's on every re-import; retired automatically (`agreed`) once the catalogue says the same; flagged `conflict` (listed first) when the catalogue changes the field to something else. `status`, `id` narrow it. The lint rule `event-correction-conflict` lists the conflicts too. |
| `event_links` | link events to the corpus without guessing (#1449). With `id`: the sources that MAY discuss the event — findings near it in time and space, passages of their text naming it (label, other names, aliases in other languages) — scored and **unconfirmed**; `confirm` writes an attestation (quote + offsets) only from a passage that names it, `reject` stops proposing one. Without `id`: the LEADS — catalogue events (GVP, NOAA, Wikidata) no source discusses, with the findings around them counted and the commands to act. A catalogue event is a lead, never evidence. The import itself is the operator's: `histmersion events import`. |
| `attestations` / `put_attestation` / `delete_attestation` | granular evidence: link a finding, event, dating, place or edge to the exact passage of a source (W3C Web Annotation selectors: quote, position, chunk, page). |
| `patch_asset` | a stored figure's metadata: kind (figure/photo/map/plan/scan), caption, licence, location and period. |
| `asset_links` / `delete_asset_link` | typed links between figures and events, findings, places, sources or articles. |
| `goals` / `put_goal` / `patch_goal` | research programmes: slug, title, status (`planned`→`seeding`→`compiled`→`reviewed`→`done`), progress notes, scope, the cost cap of their agent runs; with `slug`, a goal's sub-goals, links, schedules and approved plan. |
| `agent_state` / `delete_agent_state` | a small key-value store an agent keeps across sessions (set, get, list, delete). |

## Embedded agents (off unless the server enables them)

| tool | when to use it |
|---|---|
| `start_run` | hand a whole pipeline to the server: `enrich-source <citekey>` (summary, classification, period, findings with verbatim quotes, notes; metadata checked against OpenAlex/Crossref; `refs`/`assess`; one verified patch), `review-article <slug>` (the three-reviewer panel in parallel, merged by code into the article's review ledger; with `fix`, a fixer revises the article, each reviewer verifies the findings it claims fixed and the edited passages, and a full panel confirms; one backlog item per article lists its open MAJORs), `compile-article <slug>` (a new article, or a section appended to one, from the sources a filter returns: verified claim table, evidence model, draft, code self-check — the run **waits** until a person approves, then writes and chains a review), `plan-goal <goal>` (sub-goals, queries and DOIs checked upstream — nothing is created before approval), `currency-check <goal>` and `acquisition-sweep <goal>`. Returns the run id at once; the run is checkpointed, budgeted and resumable. `dryRun: true` runs every read and model step but writes nothing (each write is recorded on its step); `modelFor: ["role=provider:model"]` gives one role its own model for this run. |
| `run_status` | the newest runs, filtered on the server by `status` (`waiting` = for an approval; comma-separate several), `pipeline`, `origin`, the process `manager` that dispatched them, one `goal`, the `model` or `provider` a step used, `since` / `until` and `subject` (text in the target) — with `By pipeline` / `origin` / `manager` / `provider` / `model` lines of counts, paged like `job_status` (`before`); or one run's steps (configured model → the model the provider reported), tokens, cost, warnings, a dry run's unwritten writes and (`messages: true`) trace; `compare: [ids]` lays runs of one pipeline on one target side by side. |
| `list_approvals` | what runs PROPOSED for a person to decide — a status, a disagreement edge, a goal's plan, an article to publish, an article's filter, a plan of articles, a manager action from a hint — with the evidence and the quote code verified. Filtered on the server by `state` (open by default, or `approved`, `rejected`, `failed`, `all`), `kind`, `subject` (text in what it is about), `goal` and `decidedBy` (`person`, `autopilot`, `auto`), with `By kind` / `Decided by` lines of counts; paged like `job_status` (`before`). `digest: true` gives the digest instead: everything waiting for a person by kind (how many, the oldest, who decides them now, the subjects, the ids) and the manager items held for a person. |
| `decide_approval` | approve (applies a source change through the ordinary patch, or lets the waiting run apply its plan or write its article) or reject one approval. Without `id`, a whole group at once: every open approval of `kind`, about `subject`, or in `ids` (they narrow together), the oldest first, at most `limit`; `dryRun: true` lists what it would decide. |
| `goal_links` | link a goal to a source, an article, a search query or a queue item (or unlink it). |
| `goal_schedule` | a goal's `currency` and `acquisition` schedules (cron in UTC): set, remove, or list them all. Since the managers' phase 3 they are the sweeps of the goal's **watcher** `watch:<goal>` (created **paused** — resume it for them to fire; one cron, shared by both sweeps). They run only while the server's agents are on, within the cost caps. |
| `agent_models` | each step role's model **chain** (tried in order; the first model with allowance left is used) and each allowance (tokens/USD per rolling window, a reserve) with what is used, left, and when a window frees; `quota: true` shows the **subscription pools** instead (Claude plan, ChatGPT plan: each window's use against its floor, reset, reading age and source, the hold switch); `doctor: true` checks every provider (keys, the free model listing, prices, the `claude`/`codex`/`opencode` CLIs and their logins — nothing is spent). |
| `set_agent_models` | change a role's chain (`role` + `models`) or an allowance (`target` — `provider:model` or `provider:*` — + `limits` like `"2M tokens/5h"` + `reservePct`), saved over the server's config; `reset: true` goes back to config. With `pool` (`claude-plan`, `chatgpt-plan`): `hold` pauses or releases all agent use of that subscription, `floors` (`"five_hour=30, seven_day=25"`) the share of each window that must stay left; `refresh: true` (with or without `pool`) takes a fresh reading now — the ChatGPT plan through `codex app-server` (free), the Claude plan through one minimal `claude -p` turn; with `role` + `fallthrough`: whether that chain may fall from a plan below its floor to a paid key. |
| `manager` | the persistent process managers (docs/research-process-managers.md): `list`, `show` (items in flight, hints, events), `create` (`kind` review · enrich · seed · watch, `goal`, `cron`; created paused), `pause` (`runs: true` pauses its runs too), `resume`, `enqueue` an article for the `review` manager (first in line), `hold` one until a date or until a source exists, `hint` (a note its runs' fixer and skeptic read; `item` scopes it, `once` = the next run only; an `effect` given here is a model's **proposal** — a `hint-effect` approval a person decides — and `suggest: true` asks the server's model to propose one). The review manager runs `review-article` with fix on one article after another until no MAJOR is left, and stops an article with a task (omission churn, no progress, reopened or escalated findings, too many runs); a watcher `watch:<goal>` runs its area's acquisition sweep and currency check on its cron. Each line says the manager's spend today against its daily cap (and a watcher's its ingest backlog with the days to drain it). `autopilot` (no `on`: the status — per research goal its stage, managers, sources, articles, open approvals, last activity and pace, and the watchers' ingest backlog; `on: true\|false` turns the autopilot on or off). `repair-acquire` (`dryRun: true` lists what it would do): the open acquisition items a watcher's sweep created for legal open-access works move into the watchers' ingest backlog; a person's items are never touched. `focus` — the autopilot's focus (at most `max-active-goals` goals active for model work, finish-first): no `focus` (or `list`) shows the active goals with why and what each waits for, the queue in order and the goals that cannot use a slot; `focus: pin\|unpin` with `goal`, `focus: priority` with `goal` and `value`, `focus: max` with `value` (0 = no cap; no value: back to the config). `drain` — nothing new starts while the runs in flight finish (the autopilot's status says DRAINED once none is queued or running: safe for a deploy); `on: false` lifts it. `mode` — the two switches as one choice, as the web UI shows it: `mode: working` (on, nothing held back), `finish` (finish current work, then pause: the drain), `pause` (now: the autopilot off). |
| `scheduler` | the central agent scheduler: ONE decision per managers' tick admits the managers' pending work across every job type (goal plans, proposals, sweeps and their ranking, currency checks, enrichment, compiles, extensions, filters, reviews) within the AI allowance (runs at once, each plan pool's calls in flight, budgets, daily caps; a run waiting for a person holds no place), by goal priority, job type and aging, with a max wait, a minimum share per type and places for goals still gathering sources. `status` (default; `limit` = waiting items shown): the strategy, resources, the last pass's starts and the queue with why each item waits and behind what; `queue`; `why` with `item` (an item id or the target of an open item); `strategy` with `strategy` = `type-balanced` · `goal-first` · `default` switches it live. `stalls` (`days`): the unfinished goals with no progress in N days, each with the reason it stands still and the command that unblocks it. |

A CLI step (`claude-code`, `codex`, `opencode`) reaches a second, read-only MCP endpoint,
**`<public-url>/mcp/agent`**, with a **run token** the server issues for that one step: the endpoint
answers only to a live token and serves only the tools of the step's agent definition (`/mcp/agent/<agent>`;
the agent tools are `get_source`, `passages`, `search`, `facets`, `neighbors`, `query`, `get_article`, `followups`
without `apply`, `check_edits` and `article_coverage`). It is not meant for an interactive client.
